# mbfa

## Overview

MBFA is a byte-oriented general-purpose compressor: a hash-chain LZ front
end (with an optional bounded-horizon DP optimal parser), a choice of ten
entropy back ends chosen by brute-force tournament, an optional multi-file
archive container, format-aware pre-filters for common binary layouts
(3D meshes, executables, legacy Office containers), and a set of
per-format static dictionaries for small structured files. It ships as
both a library crate and a CLI (`main.rs`).

This crate is large enough that its documentation is split by subsystem
("part") rather than kept in one file. Each part below documents every
source file in that subsystem: what it does, the design decisions behind
it, any benchmark results, and its fix/problem history.

## Parts

- **[core](mbfa/core.md)** — the compression pipeline itself: the public
  `compress`/`decompress` API (`lib.rs`), the LZ scanner and its inverse
  (`encoder.rs`, `decoder.rs`), the fold/unfold orchestration that wraps
  a file in one or more compression passes (`fold.rs`, `unfold.rs`), pair
  encoding (`pairing.rs`), the opcode/token vocabulary (`opcode.rs`), the
  bitstream I/O primitives (`bitwriter.rs`, `bitreader.rs`), and the
  parallelism shim (`par.rs`).
- **[entropy](mbfa/entropy.md)** — the ten entropy back ends (Huffman
  variants v1-v6, adaptive range coders v7/v9, block-split v8, and the
  DP-driven v10 "v9-optimal"): `entropy.rs`, `entropy_v9.rs`,
  `price_table.rs`, `optimal_parse.rs`.
- **[archive](mbfa/archive.md)** — the multi-file archive container, the
  CLI, RAM-aware chunk sizing, and the standalone profiling binary:
  `archive.rs`, `archive_io.rs`, `platform.rs`, `main.rs`,
  `profile_offsets.rs`.
- **[dictionary](mbfa/dictionary.md)** — per-format static dictionaries
  used as addressable pre-history for small structured files:
  `dictionary/mod.rs` and its five format-specific dictionaries.
- **[filters](mbfa/filters.md)** — pre/post-compression byte-level
  transforms for specific binary layouts: `filters/mod.rs` and the eight
  format-specific filters (delta, BCJ, CFBF, FBX, glTF, PLY, STL) plus
  the multi-stride entropy probe.

## CI and Workflows

Five GitHub Actions workflows live in `.github/workflows/`:

- **mbfa-ci.yml** — build and test on every push/PR; also regenerates
  `others/ProjectStructure.txt` and commits it back (`[skip ci]`) when the
  file tree changes. Optional publish/deploy and other-workflow triggers
  are controlled by flags in the triggering commit message (see the
  workflow's own comments for the current flag list).
- **mbfa-archive.yml** — runs the archive-specific benchmark suite.
  Triggered by an `--archive`/`--all` commit-message flag or manual
  dispatch.
- **mbfa-corpus.yml** — runs the Canterbury Corpus benchmark. Triggered
  by a `--corp`/`--all` commit-message flag or manual dispatch.
- **mbfa-special.yml** — runs the special benchmark suite against files
  generated by `scripts/gen_special_files.py`. Triggered by a
  `--special`/`--all` commit-message flag or manual dispatch.
- **mbfa-expose.yml** — verifies the crate still builds standalone (for
  consumption by sibling repos), on push to `main`.
